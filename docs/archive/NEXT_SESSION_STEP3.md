## 0. TL;DR (30 секунд)

`python main.py` уже поднимает pystray-иконку, красит её по статусу поллера
(`idle`=зелёный, `active`=жёлтый, `error`=красный, `stopped`=серый) и даёт меню
`Status / Settings / Open Log / Exit`. Меню `Settings` запускает Electron Control Center.

**Доделать (всё мелкое):**
1. Двойной клик по иконке → открыть Control Center (сейчас нет `default`-пункта).
2. Переименовать пункт `Settings` → «Открыть Control Center» (по смыслу он это и делает).
3. Убрать консольное окно при обычном запуске (`pythonw.exe` / собранный `--windowed`).
4. Проверить, что `Exit` корректно гасит поллер-поток И иконку.

**Готово, когда:** иконка в трее, цвет меняется при реальной смене статуса,
двойной клик/меню открывает Control Center, «Exit» всё закрывает, консоли нет.

### 1.2 Логика цвета — важный нюанс

Трей берёт цвет из **внутреннего статуса поллера** (`Poller.status`:
`idle/active/error/stopped`), который меняется в реальном времени из потока поллера
через колбэк `_on_status_change`. Это **другой** сигнал, чем у Control Center
(`agent:status` в `agent_os_app/main.js:158` считает свежесть по mtime лога:
`online/stale/offline`). Это нормально: у трея есть живой поллер, ему mtime не нужен.

> MVP_PLAN.md просит «зелёный/жёлтый/красный по свежести poll». Фактически трей
> уже делает лучше — красит по реальному статусу потока. Не надо переделывать на
> mtime-логику; достаточно убедиться, что цвета соответствуют ожиданиям юзера
> (idle=на связи=зелёный, active=выполняет=жёлтый, error=проблема=красный).

## 3. ТЗ (требования)

### 3.1 Меню трея — целевой вид

```
Открыть Control Center   ← default (двойной клик по иконке делает то же)
Status
Open Log
─────────
Exit
```

- **Открыть Control Center** — это текущий `_open_settings` (`main.py:66`), только
  переименовать пункт и пометить `default=True`, чтобы двойной клик его вызывал:
  ```python
  MenuItem("Открыть Control Center", _open_settings, default=True),
  ```
- **Status** — показывает статус/URL/токен (`_show_status`, `main.py:52`). Оставить.
- **Open Log** — открывает `agent.log` (`_open_log`, `main.py:100`). Оставить.
- **Exit** — `_exit_app` (`main.py:106`). Оставить.

### 3.2 Без консольного окна

Сейчас `python main.py` показывает консоль (есть `StreamHandler(sys.stdout)`,
`main.py:25`). Варианты (выбрать по ситуации):
- **Dev-запуск:** `pythonw.exe main.py` (pythonw не создаёт консоль). Документировать в MVP_PLAN.
- **Прод:** собранный `--windowed` exe (Шаг 7) — консоли не будет автоматически.
- StreamHandler можно оставить: при `pythonw`/`--windowed` `sys.stdout` есть, но окна нет.
  Трогать логирование не обязательно.

> Не убирай файловый лог (`FileHandler`) — он нужен Control Center'у для `agent:status`,
> `events:recent`, `log:tail`. Убрать можно максимум `StreamHandler`, и то не обязательно.

### 3.3 Корректный выход

`_exit_app` уже вызывает `_poller.stop()` (ставит stop-event) и `icon.stop()`.
Поллер — daemon-поток (`poller.py:31`), он завершится. Проверить, что после «Exit»
процесс действительно умирает (нет зависшего `python.exe` в Task Manager).

### 3.4 Что НЕ трогать

- ✋ Логику `Poller` и хендлеров.
- ✋ Electron Control Center (`agent_os_app/`).
- ✋ Цвета/механику `_on_status_change` (работает корректно).
- ✋ Файловый лог (нужен Control Center'у).

## 6. Готовность (приёмка)

Закрыто, когда **все** проходят:
1. `pythonw E:\dispatch\main.py` → иконка в трее, **консольного окна нет**.
2. Цвет иконки соответствует статусу (idle=зелёный при нормальном поллинге;
   active=жёлтый во время команды; error=красный при потере сети).
3. Двойной клик по иконке **или** пункт «Открыть Control Center» поднимает окно Electron.
4. «Exit» закрывает иконку и останавливает поллер — в Task Manager не остаётся
   зависшего процесса, лог перестаёт обновляться.

## 8. Типичные грабли

| Симптом                                  | Причина                                | Что делать                                   |
|------------------------------------------|----------------------------------------|----------------------------------------------|
| Иконки в трее нет                         | pystray не стартанул / нет backend      | проверить `pip install pystray pillow`        |
| Двойной клик ничего не делает             | нет `default=True` на пункте            | пометить пункт `default=True`                 |
| «Открыть Control Center» молчит           | нет Node / `npm install` не сделан      | `npm install` в `agent_os_app/`, или legacy   |
| Консольное окно висит                     | запущено через `python.exe`             | запускать `pythonw.exe`                        |
| После «Exit» процесс жив                  | поллер не daemon / завис                | он daemon (`poller.py:31`); проверить `_exit_app` |
| Цвет не меняется                          | колбэк не доходит / `_icon` ещё None    | проверить `_on_status_change`, что `_icon` задан |
