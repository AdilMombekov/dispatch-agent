## TL;DR

- **Из 12 вкладок реально подключены к данным только 4:** Обзор (частично), Пароли и ключи (частично), Каналы связи (частично), Воркфлоу n8n (полностью), История событий (полностью).
- **8 вкладок — статичные демо-данные** (Чаты, Внешние сервисы, Умения ИИ, Skills, Сценарии, Где хранятся данные, Файлы, Дашборд-метрики «очередь» и «среднее»).
- **Главная причина**: пока workflow на Railway не починен (Шаг 1 MVP), реальной очереди / реальных диалогов / реального счёта Anthropic просто нет — UI **нечего** показывать. Поэтому вкладки заполнены умными заглушками.
- **Telegram-сообщения-«мусор»** (промежуточные «выполняю», «обрабатываю») — это правка n8n-воркфлоу, не Control Center.
- **Google Drive бэкап** — отдельная новая подсистема: Python-демон, который сидит рядом с агентом, бэкапит `Documents/`, `Desktop/`, выборочные подпапки на Drive в папку **Dispatch/**, с idle-детектом, ручным запуском и diff-парсингом.

## Часть 2 · Google Drive backup-подсистема

### 2.1 Цели

Пользователь хочет: бэкап с компа в папку **Dispatch/** на Google Drive (`adil.mombekov97@gmail.com`).

Требования (со слов):
1. Бэкапить когда компьютер **свободен и не используется** (idle).
2. **Авто-прерывание** бэкапа когда пользователь начинает работать.
3. **Ручной запуск** бэкапа в любой момент.
4. Парсинг и **сравнение содержимого** папки Drive ↔ компьютер.
5. **НЕ бэкапить** системные данные Windows и общие утилиты.
6. Ежедневный пересмотр / бэкап изменений.

### 2.2 Архитектура

```
┌──────────────────────────┐        ┌────────────────────────┐
│ Control Center (Electron)│        │ Google Drive           │
│   вкладка «Бэкап»        │◀──────▶│   /Dispatch/           │
│   статус, кнопки, журнал │  REST  │     /Documents/...     │
└──────────────────────────┘        │     /Desktop/...       │
            │                       │     /Projects/...      │
            │ IPC                   └────────────────────────┘
            ▼                                  ▲
┌──────────────────────────┐                   │
│ backup_daemon.py         │                   │
│   - idle detect          │───── google-api ──┘
│   - file scan + diff     │
│   - upload/throttle      │
│   - resume on idle       │
└──────────────────────────┘
            │
            │ scans
            ▼
   C:\Users\User\Documents\
   C:\Users\User\Desktop\
   C:\Users\User\Projects\
   (по whitelist)
```

**Два компонента:**
1. **`backup_daemon.py`** — отдельный Python-сервис рядом с агентом. Отвечает за idle-детект, сканирование, загрузку. Может запускаться как поток внутри `main.py` или как отдельный процесс.
2. **Вкладка «Бэкап»** в Control Center — UI: статус, прогресс, журнал, кнопки.

### 2.3 Что бэкапить

**Whitelist (по умолчанию):**
- `C:\Users\User\Documents\**` — всё, кроме `My Pictures/Screenshots`, `My Music`
- `C:\Users\User\Desktop\**` — только файлы, не временные
- `C:\Users\User\Downloads\` — **не** бэкапить (большой и временный)
- `E:\dispatch\config.json`, `E:\dispatch\workflow_fixed.json` — критичные конфиги проекта
- `C:\Users\User\Documents\Obsidian\` — vault (если есть)
- Папки кода: настраиваемые в UI (пользователь добавит свои `D:\Projects\` и т.п.)

**Blacklist (никогда):**
- Системные: `C:\Windows\`, `C:\Program Files\*\`, `C:\Program Files (x86)\*\`
- Кэши: `node_modules`, `__pycache__`, `.venv`, `venv`, `dist`, `build`, `*.egg-info`
- Большие бинарные: `*.iso`, `*.vhd`, `*.exe` (опционально — только в whitelisted папках)
- Временные: `*.tmp`, `~$*`, `.DS_Store`, `Thumbs.db`

**Лимиты:**
- Один файл > 100 МБ — спросить пользователя (флаг в UI «бэкапить большие файлы»)
- Папка > 5 ГБ — предупреждение в UI

### 2.4 Когда (idle detection)

Windows предоставляет `GetLastInputInfo` (через `ctypes`). Каждые 30 секунд:
```python
import ctypes
class LASTINPUTINFO(ctypes.Structure):
    _fields_ = [('cbSize', ctypes.c_uint), ('dwTime', ctypes.c_uint)]
def idle_seconds():
    info = LASTINPUTINFO(ctypes.sizeof(LASTINPUTINFO), 0)
    ctypes.windll.user32.GetLastInputInfo(ctypes.byref(info))
    return (ctypes.windll.kernel32.GetTickCount() - info.dwTime) / 1000
```

**Правила:**
- Idle > **5 минут** → можно начинать бэкап.
- Idle < **30 секунд** → немедленно поставить на паузу (текущий файл доливается до конца, потом стоп).
- Throttle: не больше **10 МБ/с** аплоада, чтобы не мешать другим сетевым задачам.
- Окно «не бэкапить» (опционально): 09:00–22:00 если на этой машине работают.

### 2.5 Ручной запуск

В UI кнопки:
- **Запустить сейчас** — игнорирует idle-проверку, запускает бэкап (с предупреждением).
- **Только проверить (dry-run)** — сравнивает, ничего не загружает, показывает что бы было.
- **Пауза / Продолжить**.
- **Отмена** — мягко завершает текущий файл и останавливается.

### 2.6 Парсинг и сравнение Drive ↔ ПК

**Алгоритм:**
1. Локально: сканируем whitelist-папки → строим индекс `{relative_path: {size, mtime, sha256-prefix}}`. Хэш только первых 64 КБ файла (быстрая «отпечатка»).
2. Drive: для папки `Dispatch/` — listing через API → индекс `{path: {size, modifiedTime, md5Checksum}}`.
3. Сравнение:
   - **только локально** → нужно загрузить.
   - **только в Drive** → опционально вернуть (или просто отметить «есть в облаке»).
   - **в обоих, но размер/mtime отличаются** → обновить (если локальный новее) или предупредить.
4. Результат сравнения → таблица в UI с фильтрами «нужно загрузить / обновить / удалить из Drive / синхронизировано».

**Индекс хранится** локально как `%APPDATA%\AgentOS\backup_index.json` — чтобы не пересчитывать каждый раз. Обновляется по `watchdog` (новые файлы).

### 2.7 Технический стек

- **Авторизация Google Drive:** OAuth 2.0 через `google-auth-oauthlib`. Token хранится в `%APPDATA%\AgentOS\google_token.json`. Scope: `https://www.googleapis.com/auth/drive.file` (только файлы созданные приложением — безопаснее, чем full `drive`).
- **Drive API:** `google-api-python-client`.
- **Resumable upload** — обязательно для больших файлов.
- **Watchdog** — Python `watchdog` для отслеживания изменений в реальном времени.
- **Idle:** Windows API через `ctypes` (см. §2.4).
